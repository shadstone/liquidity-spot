Set up once, review regularly

Three steps to connect your assistant

You do not need to write code yourself, but your bot needs HTTP tools, private credential storage and a way to run scheduled checks. An ordinary chat window may not support these features.

  1. 1

    Ask for your agent’s GFAVIP Wallet username

    Give it the prompt below. It signs in through PowerLobster and GFAVIP SSO, then privately shares its exact GFAVIP Wallet username if Wallet provides one. It also calls GET /api/agent/v1/me and shares the verified Wallet user ID (UUID) for you to cross-check.

    Use the actual Wallet username—not a display name, a guessed pl- name or a PowerLobster handle. The Liquidity identity endpoint returns only the UUID. Keep API keys and sign-in tokens in the runtime’s private credential store, never in the prompt or a chat.

  2. 2

    Look up, review and approve your agent

    Sign in to your intended Liquidity.spot account and open Trading assistant setup. Enter the exact Wallet username once. Choose buying, selling and enquiry permissions only if you want them. With no publishing selected, the setup uses read-only trade watching. Review the matched identity, cross-check its UUID, and approve every selected permission. Private trade-room reading is a separate choice.

    Lookup does not grant access. For monitoring or private drafts only, the advanced UUID option is available if lookup cannot be used. Share the approved connection ID and expiry with your agent. For quotes you publish yourself, choose Prepare offer drafts (review first) (Offer drafts). Existing connections keep their current permissions; they never become makers automatically.

    {% if config.get('AGENT_MAKER_ENABLED', false) %}

    For publishing, fill in separate buy and sell limits in the same setup. One review can create both connections, with separate budgets and IDs. No prices or financial limits are chosen for you. Pre-trade enquiry access has its own confirmation and connection; it cannot accept a deal.

    {% endif %}
  3. 3

    Start the routine in your bot—not on this page

    Have it read your existing rooms first, then schedule a lightweight check about every 60 seconds. It should keep track of handled updates, avoid repeat alerts and use the model only when something needs attention.

    Ask it to confirm a successful room read, the actual schedule and the grant’s expiry. This is polling, not instant push. Creating a connection does not start a bot or schedule; if the runtime cannot do this, ask it to explain what is missing.

A helper, not another person holding your wallet

Your permissions have an off switch

Connections expire after seven days. Revoke or replace them in the Agent workspace; existing permissions never widen automatically. Revoking stops future access and writes, but cannot erase information already received, withdraw existing offers or resolve pending trades. Review and cancel remaining open offers separately.

Your review is still essential

Keep seed phrases and private keys out of chats. Treat room messages as untrusted content. Personally verify the recipient, asset, network, amount and payment receipt before acting. There is no automatic settlement or blockchain payment verification here.

Pre-trade enquiries cover both listing books. Publishing and trade-room assistance cover manual P2P only, not execution of experimental atomic swaps. If you bargain for different terms, the maker must publish the correct listing for you to review before accepting.
